# 5.5 Simulation and operations

Goal: find the bugs that only show up in rare combinations, measure throughput, and give staff tools for the cases that need a person.

## Deterministic simulation

The test is `services/switch-service/test/simulation.test.ts`. It runs the real `SagaEngine` against a `FakeBankNetwork` (an in-memory adapter and ledger) and a `FakeClock`, with one seeded PRNG driving:

- the payments,
- the fault each bank call gets (ERROR, REFUSED, TIMEOUT_BEFORE, TIMEOUT_AFTER_COMMIT, DROP_AFTER_COMMIT),
- the latency,
- hold expiry,
- process crashes, which restart with a new owner after the lease expires,
- backoff jitter.

When the run ends, every seed must satisfy all of these:

- every payment is terminal
- every bank balances
- no step ran twice at a bank
- COMPLETED means exactly one credit and one capture
- REVERSED and DEBIT_FAILED mean nothing was captured and every credit was reversed
- no active holds are left behind
- each customer balance equals the opening deposit plus the completed payments
- the switch settlement GLs net to zero
- total customer money is unchanged

Commands:

- `npm run sim:switch` runs 30 seeds.
- `SIM_SEEDS=200 npm run sim:switch` runs more seeds.
- `SIM_SEED=17 npm run sim:switch` replays one seed exactly.

## Load

- `tests/e2e/phase-5.5.test.ts` sends 80 payments with 16 in flight across three banks. All of them must complete, p99 time-to-final must be under 5 s, every balance must be exact and the ledger invariants must hold.
- `npm run load:switch` runs the same kind of test against a running `npm run dev` stack. It creates its own customers and staff. You can set `LOAD_PAYMENTS`, `LOAD_CONCURRENCY` and `LOAD_PAIRS`.

## Staff tools (SWITCH_OPS or ADMIN)

| Call | What it does |
|---|---|
| `GET /api/switch/ops/txns?state=MANUAL_REVIEW` | Lists transactions, optionally filtered by state |
| `GET /api/switch/ops/txns/:id?inquire=true` | Full trace (steps, transitions, ops actions) plus live status from both banks |
| `POST /api/switch/ops/txns/:id/retry` `{ reason }` | Resumes from the state before review |
| `POST /api/switch/ops/txns/:id/reverse` `{ reason }` | Compensates what the switch recorded. If the review came from DEEMED, it asks the bank first. |
| `GET /api/switch/ops/metrics?windowMinutes=15` | States, success rate, latency percentiles, outcomes per bank, breakers, bulkheads |
| `GET /api/switch/ops/breakers` | Breaker and bulkhead state per bank |

Every retry or reverse writes an `ops_actions` row and a transition owned by `ops:<staffId>`.
