# 5.2 Saga orchestrator

Goal: move the money between banks, and make every business failure end in a defined state.

## States

```
INITIATED -> RISK_PASSED -> DEBIT_HELD -> CREDITED -> COMPLETED
                 |              |             |
            DEBIT_FAILED   CREDIT_FAILED   REVERSING (capture declined, e.g. HOLD_EXPIRED)
                                |             |
                            REVERSING ----> REVERSED
any non-terminal state -> MANUAL_REVIEW (adapter mismatch, compensation declined)
```

The table is in `src/machine.ts`. The terminal states are COMPLETED, DEBIT_FAILED, REVERSED and MANUAL_REVIEW.

## Build

- `src/saga.ts` `SagaEngine.drive(txnId)` repeats the next step until the payment is terminal or parked.
- Request bodies are built from the stored `txns` row (`stepRequest`), so every retry is byte-for-byte identical.
- Write-ahead step log: `saga_steps` gets a STARTED row before the bank call. After the call that row is finished with OK, BUSINESS, TRANSIENT, UNKNOWN or MISMATCH.
- Every state change writes a `txn_transitions` row and emits events in the same transaction.
- REVERSING first reverses the payee credit if there is one, then releases the payer hold if it isn't captured, then moves to REVERSED.
- Fraud is stubbed by `allowAllRisk`.

## Tests

- `test/units.test.ts`: transition table.
- `test/saga.test.ts`: happy path, step log written before the call, same-bank payment, insufficient funds, credit declined, hold expired before capture, reversal declined, adapter mismatch.
- `tests/e2e/phase-5.2.test.ts`: Rs 500 between two banks, insufficient funds, double click, same-bank payment, payee bank down. Every test ends with the ledger invariants check.
